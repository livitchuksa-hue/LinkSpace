# REST API Linkspace

Базовый URL (разработка): `http://127.0.0.1:8080/api`

Формат данных: `application/json`

## Objects — информационные объекты

| Метод | Endpoint | Назначение |
|-------|----------|------------|
| `GET` | `/api/objects` | Список всех объектов |
| `GET` | `/api/objects/{id}` | Объект по идентификатору |
| `POST` | `/api/objects` | Создание объекта |
| `PUT` | `/api/objects/{id}` | Обновление объекта |
| `PUT` | `/api/objects/{id}/position` | Обновление координат узла |
| `POST` | `/api/objects/{id}/open` | Отметка последнего открытия объекта |
| `DELETE` | `/api/objects/{id}` | Удаление объекта и его связей |

### Тело запроса `POST` / `PUT`

| Поле | Тип | Описание |
|------|-----|----------|
| `title` | string | Заголовок (обязательно) |
| `type` | string | `NOTE`, `FILE`, `FOLDER`, `LINK` |
| `description` | string | Краткое описание |
| `content` | string | Текст заметки |
| `path` | string | Локальный путь к файлу/папке |
| `url` | string | Интернет-ссылка (`http`/`https`) |
| `disk` | string | Буква/имя диска для локального материала |
| `fileSize` | number | Размер файла в байтах |
| `fileCreatedAt` | string | ISO-дата создания файла |
| `fileModifiedAt` | string | ISO-дата изменения файла |
| `x` | number | Координата X на холсте |
| `y` | number | Координата Y на холсте |
| `color` | string | Пользовательский цвет узла `#rrggbb` (опционально) |
| `width` | number | Ширина карточки узла (опционально) |
| `height` | number | Высота карточки узла (опционально) |

Для `FILE` и `FOLDER` поле `path` обязательно. Для `LINK` обязательно корректный `url`.

### Ответ

Включает поля запроса плюс `id`, `createdAt`, `updatedAt`, `lastOpenedAt`.

## Connections — связи между узлами

| Метод | Endpoint | Назначение |
|-------|----------|------------|
| `GET` | `/api/connections` | Список всех связей |
| `GET` | `/api/connections/{id}` | Связь по идентификатору |
| `POST` | `/api/connections` | Создание связи |
| `PUT` | `/api/connections/{id}` | Обновление связи |
| `DELETE` | `/api/connections/{id}` | Удаление связи |

### Тело запроса

| Поле | Тип | Описание |
|------|-----|----------|
| `sourceId` | number | ID исходного объекта |
| `targetId` | number | ID целевого объекта |
| `label` | string | Подпись связи (опционально) |
| `color` | string | Цвет линии связи `#rrggbb` (опционально) |

Связь не может соединять объект сам с собой, а дублирующая пара в любом направлении отклоняется.

## Regions — визуальные области

| Метод | Endpoint | Назначение |
|-------|----------|------------|
| `GET` | `/api/regions` | Список областей |
| `GET` | `/api/regions/{id}` | Область по идентификатору |
| `POST` | `/api/regions` | Создание области |
| `PUT` | `/api/regions/{id}` | Обновление области |
| `DELETE` | `/api/regions/{id}` | Удаление области |

### Тело запроса

| Поле | Тип | Описание |
|------|-----|----------|
| `name` | string | Название области |
| `color` | string | Цвет заливки области в формате `#rrggbb` (например, `#3b82f6`) |
| `coordinates` | string/JSON | Вершины контура: `[{"x":0,"y":0}, ...]` |
| `shape` | string | Форма области: `polygon` (по умолчанию), `rectangle` или `ellipse` |

## Settings — настройки рабочего пространства

| Метод | Endpoint | Назначение |
|-------|----------|------------|
| `GET` | `/api/settings` | Все настройки как map `key -> value` |
| `GET` | `/api/settings/{key}` | Одна настройка |
| `PUT` | `/api/settings/{key}` | Создание/обновление настройки |
| `DELETE` | `/api/settings/{key}` | Удаление настройки |

Тело `PUT`:

```json
{ "value": "строка или JSON" }
```

Используемые ключи:

- `graph.view` — JSON с `x`, `y`, `scale`;
- `graph.fields` — JSON с видимыми полями узлов (`title`, `type`, `disk`, `dates`).

## Ошибки

Типичные ответы:

| HTTP | Когда |
|------|-------|
| `400` | Ошибка валидации или некорректные данные |
| `404` | Ресурс не найден |
| `500` | Внутренняя ошибка сервера |

Тело ошибки (примерно):

```json
{
  "status": 404,
  "error": "Not Found",
  "message": "Object not found: 42"
}
```

## Статус реализации

MVP реализован: CRUD объектов/связей/областей, позиции узлов, метаданные локальных файлов, отметка открытия и настройки графа. Дальнейшие функции (поиск, теги, несколько рабочих пространств) планируются отдельными этапами.
